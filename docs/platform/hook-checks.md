# Isolated Stroq hook checks

**Agents & coverage → Test Stroq hook** runs two fixed input events through the built Stroq CLI without starting an agent or requesting model inference. Choose workspace or user scope, preview the captured configuration, then explicitly start. Opening the dialog or refreshing history never starts a check.

After Connect, the receipt links to **Agents & coverage → Check history → Stroq hook** with the actual agent, source scope and installed source fingerprint. A fresh explicit preview must still match that fingerprint before Start is available. If settings changed, the handoff refuses to run; open a new selection to inspect the current source. A review-required setup stays review-required, and approval/restart remain separate. A workspace source can affect all workspaces when it resolves to the user's home; the setup receipt preserves that impact.

The Stroq hook history page retains exact result links scoped to the current workspace. An absent, foreign or malformed selection cannot silently show a different result. Agent cards show the latest recorded attempt for each selected source, including a newer incomplete or cancelled check rather than an older pass. Attention and incomplete checks also link from the protection queue; successfully recorded checks do not add attention rows. **In-agent** history remains separate at its existing URL. Reading either history only issues local GET requests.

The selected source must contain the exact current Stroq registration. Its bytes, file and directory identities, current policy and verified runtime are bound before preview, before execution and after execution. A changed or unreadable binding refuses a completed report. Foreign registrations are never executed; the process uses the fixed Node executable and CLI argument array, with no shell interpolation.

Each probe has an independent temporary home, project, Stroq data directory and restricted environment. One event describes an ordinary command; the other describes an encoded fetch-and-execute command using the reserved `stroq.invalid` address. These strings are supplied only as JSON hook input. The described commands are never executed. The copied policy is evaluated independently with the actual core engine, then the CLI response is compared with both that expectation and its isolated, verified audit event. `ask` remains visible in audit evidence; Codex encodes it as a deny. The check is offered for Claude Code, Cursor and Codex; Windsurf is not offered.

**Passed** requires matching responses and audit evidence for both probes, with ordinary work allowed and the encoded fetch denied. **Attention** means the responses match a policy with different choices. **Failed** means a response or its audit evidence did not match. Process failure, cancellation, deadline, invalid reports and cleanup failure remain separate failed attempts; an internal fail-closed response is not accepted as a successful policy check.

This establishes isolated execution of the captured Stroq adapter. It does not establish that an agent loaded the selected configuration, approved it or stopped an action. No provider requests are made. **Test in agent…** remains a separate explicit live workflow with subscription usage consent.

Only bounded derived reports are retained, in a private `console/hook-checks-<workspace-id>.json` file under the selected Stroq home. The workspace identity includes the canonical project path and directory identity. History holds the latest 32 attempts, with no automatic time expiry. Raw subprocess output, test commands, policy text, environment values and temporary paths are not retained in reports. Broken or unsafe storage is reported and is not overwritten. A report describes its captured revision and time; it does not claim current host enforcement. Restarted unfinished attempts become failed records.

Installation diagnostics are also captured reports. Their policy/runtime binding does not cover every diagnostic input or ongoing host liveness, so their summary remains **Recorded diagnostics**. Use a new installation check to reread setup and the current agent configuration view for current registration coverage.

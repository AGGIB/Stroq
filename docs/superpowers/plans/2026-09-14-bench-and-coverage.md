# False-Positive Bench and Coverage Artifact Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the two numbers no vendor in the field publishes — a false-positive rate on benign developer traffic, and a machine-generated control mapping against a canonical taxonomy — each reproducible by anyone on their own files, and each regenerated by CI so no human ever types it.

**Architecture:** `stroq bench` scans a vendored corpus of real third-party developer documentation and reports how much of it the shipped rule set flags. `stroq coverage` joins the corpus's ATLAS tags against the vendored MITRE ATLAS denominator through a committed scope declaration that says which techniques a local action firewall can address at all and why the rest are out of scope, then emits a table, a JSON record and an ATT&CK-Navigator layer. A CI job regenerates the coverage artifact and fails on any diff, so the documented mapping cannot drift from the code the way the surveyed competitor's did.

**Tech Stack:** TypeScript (ESM, Node ≥ 22), vitest, zod 4.5.4, yaml 2.9.0, tsup. No new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-13-coverage-and-exposure-design.md` §5d and §5e. §5a–§5c shipped in `docs/superpowers/plans/2026-09-14-attack-matrix-and-fuzzer.md`; Part 4 (§6) is the next plan and is specified by that plan's escape list and gaps table.

## Global Constraints

- Node ≥ 22 (`packages/cli/package.json` `engines`). Target `node22`.
- No new runtime dependencies. `packages/cli` `dependencies` stays exactly `yaml@2.9.0` and `zod@4.5.4`.
- Everything runs offline at runtime. The only network steps in this plan are one-time `curl`/fetch calls that vendor third-party files into the repository, each pinned to a commit and recorded with its sha256.
- **No human writes a coverage number, ratio, percentage or badge anywhere.** Every published figure is produced by a command and regenerated by CI. The one number a human may write is a count of things shipped, and even that should be generated where it is cheap to do so. This is the single rule this whole plan exists to honour — the surveyed competitor's `docs/owasp-mapping.md` disagrees with its own `owasp_agentic.go` on six of ten categories, and this is how that happens.
- Tests live in `packages/cli/test/**/*.test.ts`; run with `node node_modules/vitest/vitest.mjs run <path>`. **The sandbox hangs on any `node_modules/.bin` shim or shebang script** — always invoke the `.mjs`/`.js` entry through `node` directly. Same for `node node_modules/typescript/bin/tsc`, `node node_modules/prettier/bin/prettier.cjs` and `node node_modules/tsx/dist/cli.mjs`.
- Coverage thresholds in `vitest.config.ts`: lines/functions/statements 80, branches 70.
- Commit style: `<type>: <description>` (feat, fix, refactor, docs, test, chore, perf, ci), body wrapped at ~72 chars, trailer `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`.
- Work on branch `feat/bench-and-coverage`, branched from `feat/attack-matrix` (or from `main` once that branch has merged — check before branching; every task here depends on the ATLAS vendoring and the scenario tags it shipped).

## What already exists, and the facts this plan is built on

Verified on 2026-09-14 against this repository — do not re-derive these from memory:

- `loadBundledRules()` (`packages/core/src/rules/bundle.ts`) returns **599** compiled rules: the bundle holds 608 and excludes the 9 listed in its `disabled` array.
- **`rules/fixtures/benign` is a build-time gate, not a benchmark.** `scripts/build-rules.ts` runs every rule against those 10 files and *disables* any ATR rule that fires on one (that is where the 9 come from). Benchmarking the shipped rule set against the same 10 files therefore reports a false-positive rate of approximately zero **by construction**, and publishing that number would be dishonest. The bench corpus must be disjoint from it, and Task 1 enforces that with a test rather than a convention.
- The motivating measurement (spec E1) is 534 of 4,824 files flagged — 11.1% — on a third-party skill library that cannot be vendored. It is the reason this command exists; it is **not** the number to publish. The published figure is whatever `stroq bench` reports against the committed corpus.
- `packages/cli/src/coverage/atlas.ts` exports `loadAtlas()`, `atlasIds()` and `ATLAS_ID`, reading the generated `atlas.json` (197 techniques, 83 of them sub-techniques) derived from `vendor/atlas/ATLAS-2026.08.yaml` by `pnpm build:atlas`, with `pnpm check:atlas` gating it in CI.
- Every scenario carries `atlas: string[]` (validated against that denominator at parse time) and `asi: string[]` (validated against `/^ASI(?:0[1-9]|10)$/`, currently empty on every scenario). The corpus is 20 scenarios: 12 documented incidents, 8 synthetic cells.
- ATLAS v6 carries **no** technique→tactic edge. MITRE's own ATLAS Navigator layers use `"domain": "atlas-atlas"`, `versions: { layer: "4.3", navigator: "4.6.4" }`, a `metadata` entry naming the ATLAS data version, and omit the optional per-technique `tactic` field — which the v4.5 layer format documents as optional, resolving placement from the loaded matrix.

**Why a manifest and not a directory of files someone dropped in.** The published false-positive rate is only worth something if a reader can reproduce it. A directory of pasted text proves nothing.

**Choosing the corpus.** Every source must be Apache-2.0 or a licence compatible with redistribution inside an Apache-2.0 repository, and must be *real developer documentation* — not text written for this benchmark. Bias the selection toward the failure distribution spec E1 identified: documentation that discusses credentials, tokens, prompts, shell commands, agent instructions and CI. The initial manifest below is eight sources across six Apache-2.0 projects; all eight were confirmed reachable on 2026-09-14.

```ts
// scripts/fetch-bench-corpus.ts
//
// Fetches the vendored benign corpus from the manifest and records each file's
// resolved commit and sha256. Default mode writes files and updates the manifest;
// `--check` (CI) re-hashes the committed files and fails on any mismatch, writing
// nothing and touching the network not at all.
import { createHash } from 'node:crypto';
import { mkdirSync, readFileSync, writeFileSync } from 'node:fs';
import { dirname, join, resolve } from 'node:path';

const root = resolve(import.meta.dirname, '..');
const manifestFile = join(root, 'vendor/bench-corpus/sources.json');
const filesDir = join(root, 'vendor/bench-corpus/files');

interface Source {
  repo: string;
  ref: string;
  path: string;
  license: string;
  commit: string;
  sha256: string;
}
interface Manifest {
  note: string;
  sources: Source[];
}

const localPath = (s: Source): string =>
  join(filesDir, s.repo.replace('/', '-'), s.path.split('/').pop() ?? s.path);

const hash = (buf: Buffer): string => createHash('sha256').update(buf).digest('hex');

/** Resolves a ref to the commit it points at, so the manifest pins bytes, not a branch. */
async function resolveCommit(repo: string, ref: string): Promise<string> {
  const res = await fetch(`https://api.github.com/repos/${repo}/commits/${ref}`, {
    headers: { accept: 'application/vnd.github.sha' },
  });
  if (!res.ok) throw new Error(`cannot resolve ${repo}@${ref}: ${res.status}`);
  return (await res.text()).trim();
}

async function fetchFile(s: Source, commit: string): Promise<Buffer> {
  const url = `https://raw.githubusercontent.com/${s.repo}/${commit}/${s.path}`;
  const res = await fetch(url);
  if (!res.ok) throw new Error(`cannot fetch ${url}: ${res.status}`);
  return Buffer.from(await res.arrayBuffer());
}

const manifest = JSON.parse(readFileSync(manifestFile, 'utf8')) as Manifest;
const checkMode = process.argv.includes('--check');

if (checkMode) {
  let bad = 0;
  for (const s of manifest.sources) {
    const actual = hash(readFileSync(localPath(s)));
    if (actual === s.sha256) continue;
    process.stderr.write(`${s.repo}/${s.path}: sha256 mismatch\n`);
    bad += 1;
  }
  if (bad > 0) {
    process.stderr.write(
      `bench corpus is not what the manifest records: run "pnpm fetch:bench-corpus" and commit the result\n`,
    );
    process.exitCode = 1;
  } else {
    process.stdout.write(`bench corpus is current (${manifest.sources.length} files)\n`);
  }
} else {
  for (const s of manifest.sources) {
    const commit = s.commit !== '' ? s.commit : await resolveCommit(s.repo, s.ref);
    const body = await fetchFile(s, commit);
    const file = localPath(s);
    mkdirSync(dirname(file), { recursive: true });
    writeFileSync(file, body);
    s.commit = commit;
    s.sha256 = hash(body);
    process.stdout.write(`${s.repo}/${s.path} @ ${commit.slice(0, 7)}\n`);
  }
  writeFileSync(manifestFile, `${JSON.stringify(manifest, null, 2)}\n`);
  process.stdout.write(`bench corpus: ${manifest.sources.length} files\n`);
}
```

- Produces:
  - `interface RuleHit { readonly ruleId: string; readonly title: string; readonly files: number }`
  - `interface BenchReport { readonly version: 1; readonly corpus: string; readonly files: number; readonly bytes: number; readonly rules: number; readonly flagged: number; readonly rate: number; readonly byRule: readonly RuleHit[]; readonly flaggedFiles: readonly string[] }`
  - `function defaultCorpusDir(): string | null`
  - `function runBench(dir: string): BenchReport`
  - `function formatBench(report: BenchReport, opts?: { readonly verbose?: boolean }): string`
  - `function runBenchCommand(argv: readonly string[]): Promise<number>`

**Where the default corpus lives, and why it is not in the tarball.** The vendored corpus sits in `vendor/bench-corpus/files`, outside `packages/cli`, so it does **not** ship to npm — `packages/cli/package.json`'s `files` array publishes `dist` and three docs, and release 0.10.1 deliberately halved the unpacked package size. Bundling a megabyte of third-party documentation to support one command would undo that.

So `defaultCorpusDir()` resolves the vendored directory relative to the package root and returns `null` when it is absent, which is exactly the case for an npm install. `stroq bench` with no `--corpus` then exits 1 with a message that names `--corpus <dir>` and says the vendored corpus lives in the repository. That is honest and useful: the number we publish is generated in the repository by CI, and the command a user runs is `stroq bench --corpus ~/my-docs`, which is the reproduction the spec actually promises.

**`rate` is computed, never typed.** It is `flagged / files`, carried as a number in the JSON and rendered as a percentage by `formatBench`. A generated percentage is fine — the constraint is that no human writes one.

```ts
// packages/cli/src/bench/run.ts
import { existsSync, readFileSync, readdirSync, statSync } from 'node:fs';
import { join } from 'node:path';
import { loadBundledRules, scanContent } from '@stroq/core';

/** Text extensions only: the corpus is documentation, and a binary would measure nothing. */
const TEXT = /\.(?:md|rst|txt|adoc)$/i;
/** Files larger than this are skipped and reported as skipped; docs are small. */
const MAX_FILE_BYTES = 1024 * 1024;

export interface RuleHit {
  readonly ruleId: string;
  readonly title: string;
  /** How many files in the corpus this rule fired on. */
  readonly files: number;
}

export interface BenchReport {
  readonly version: 1;
  readonly corpus: string;
  readonly files: number;
  readonly bytes: number;
  /** How many rules the shipped bundle enabled for this run. */
  readonly rules: number;
  readonly flagged: number;
  /** flagged / files, computed — never typed by a human. */
  readonly rate: number;
  /** Most files first, so the worst offender is the headline. */
  readonly byRule: readonly RuleHit[];
  readonly flaggedFiles: readonly string[];
}

function walk(dir: string, out: string[]): void {
  for (const name of readdirSync(dir)) {
    const full = join(dir, name);
    if (statSync(full).isDirectory()) walk(full, out);
    else if (TEXT.test(name)) out.push(full);
  }
}

/**
 * The vendored corpus, or null when it is not on disk — which is the normal case for
 * an npm install, since `vendor/` is outside the published package. The caller turns
 * that null into a message naming `--corpus`.
 */
export function defaultCorpusDir(): string | null {
  const dir = new URL('../../../../vendor/bench-corpus/files', import.meta.url).pathname;
  return existsSync(dir) ? dir : null;
}

export function runBench(dir: string): BenchReport {
  const rules = loadBundledRules();
  const files: string[] = [];
  walk(dir, files);
  files.sort();

  const perRule = new Map<string, RuleHit>();
  const flaggedFiles: string[] = [];
  let bytes = 0;

  for (const file of files) {
    const size = statSync(file).size;
    bytes += size;
    if (size > MAX_FILE_BYTES) continue;
    const result = scanContent(rules, readFileSync(file, 'utf8'));
    if (result.verdict !== 'suspect') continue;
    flaggedFiles.push(file);
    // Attribute the file to every rule that fired on it, deduped: one file that trips
    // the same rule through two variants is one file for that rule, not two.
    for (const id of new Set(result.matches.map((m) => m.ruleId))) {
      const match = result.matches.find((m) => m.ruleId === id);
      const prev = perRule.get(id);
      perRule.set(id, {
        ruleId: id,
        title: match?.title ?? id,
        files: (prev?.files ?? 0) + 1,
      });
    }
  }

  return {
    version: 1,
    corpus: dir,
    files: files.length,
    bytes,
    rules: rules.length,
    flagged: flaggedFiles.length,
    rate: files.length === 0 ? 0 : flaggedFiles.length / files.length,
    byRule: [...perRule.values()].sort((a, b) => b.files - a.files),
    flaggedFiles,
  };
}

const percent = (rate: number): string => `${(rate * 100).toFixed(1)}%`;

export function formatBench(
  report: BenchReport,
  opts: { readonly verbose?: boolean } = {},
): string {
  const lines = [
    `stroq bench: ${report.files} files, ${Math.round(report.bytes / 1024)} KB, ${report.rules} rules`,
    `flagged:   ${report.flagged} / ${report.files}   (${percent(report.rate)})`,
  ];
  if (report.byRule.length === 0) {
    lines.push('', 'Nothing in this corpus trips a rule.');
  } else {
    lines.push('');
    for (const hit of report.byRule) {
      lines.push(
        `  ${hit.ruleId.padEnd(18)} ${hit.title.slice(0, 48).padEnd(48)} ${hit.files} file${hit.files === 1 ? '' : 's'}`,
      );
    }
  }
  if (opts.verbose && report.flaggedFiles.length > 0) {
    lines.push('', 'Flagged files:', ...report.flaggedFiles.map((f) => `  ${f}`));
  }
  lines.push('', `corpus: ${report.corpus}`);
  return `${lines.join('\n')}\n`;
}
```

```ts
// packages/cli/src/coverage/scope.ts
import { readFileSync } from 'node:fs';
import { z } from 'zod';
import { ATLAS_ID } from './atlas.js';

export interface ScopedTechnique {
  readonly id: string;
  /** What Stroq does NOT do for this technique, or null when coverage is unqualified. */
  readonly limitation: string | null;
}

export interface ExclusionGroup {
  /** Why a local action firewall cannot address these, in a sentence a reader can weigh. */
  readonly reason: string;
  readonly ids: readonly string[];
}

export interface AtlasScope {
  readonly atlasRelease: string;
  readonly inScope: readonly ScopedTechnique[];
  readonly outOfScope: readonly ExclusionGroup[];
}

const ScopeSchema = z.object({
  atlasRelease: z.string().min(1),
  inScope: z
    .array(z.object({ id: z.string().regex(ATLAS_ID), limitation: z.string().nullable() }))
    .min(1),
  outOfScope: z
    .array(z.object({ reason: z.string().min(31), ids: z.array(z.string().regex(ATLAS_ID)).min(1) }))
    .min(1),
});

const SCOPE_URL = new URL('./scope.json', import.meta.url);
let cached: AtlasScope | null = null;

export function loadScope(): AtlasScope {
  cached ??= ScopeSchema.parse(JSON.parse(readFileSync(SCOPE_URL, 'utf8')));
  return cached;
}
```

- [ ] **Step 4: Author `scope.json`**

This is judgement work, not transcription. Method:

1. List every technique with `node node_modules/tsx/dist/cli.mjs -e` or a scratch script that prints `id name` from `loadAtlas()`.
2. Put a technique **in scope** only if a hook-based local firewall could plausibly see the action or the content involved — prompt injection through content the agent reads, tool invocation, credential access through the agent's own tools, agent configuration changes, supply-chain compromise arriving through the agent's package or tool installs, data destruction through tool calls.
3. Group everything else into a handful of exclusion groups with an honest reason. Expect groups along these lines, but write the reasons yourself after reading the techniques rather than copying these: attacks on the model or its training data, which happen before any agent action reaches a hook; attacks requiring physical or infrastructure access Stroq has no view of; reconnaissance and resource-development activity that produces no agent action; multi-agent and inter-agent communication, which Stroq does not mediate today; techniques targeting the deployed model-serving stack rather than a developer's agent.

A limitation string is not an apology; it is the sentence that makes the coverage claim survivable when a reader tests it.

Every in-scope technique that no scenario tags will be reported as `not_covered` by Task 5 — that is expected and is the point. Do not restrict the in-scope set to what the corpus already covers; that would make the coverage number self-fulfilling.

  - `interface AsiCoverage { readonly id: string; readonly name: string; readonly scenarios: readonly string[] }`
  - `interface CoverageReport { readonly version: 1; readonly atlasRelease: string; readonly asiEdition: string; readonly scenarios: { readonly total: number; readonly documented: number; readonly synthetic: number }; readonly techniques: readonly TechniqueCoverage[]; readonly summary: { readonly inScope: number; readonly covered: number; readonly partial: number; readonly notCovered: number }; readonly asi: readonly AsiCoverage[] }`

**How status is derived, and why there is no percentage.** A technique is `covered` when at least one scenario tags it and the scope file records no limitation; `partial` when a scenario tags it and a limitation is recorded; `not_covered` when no scenario tags it. Uncovered techniques print in the same summary line as covered ones, never in a separate section a reader can skip.

The headline is the **depth** number — scenarios shipped, split into documented incidents and synthetic cells — not a ratio. Anyone who wants a ratio can compute it from the artifact; that is their claim to make, not ours. This follows Atomic Red Team's practice, which the spec cites: asked for a coverage percentage it declines and hands over a Navigator layer.

**The Navigator layer's shape is copied from MITRE's own ATLAS layers**, not invented: `"domain": "atlas-atlas"`, `versions: { layer: "4.3", navigator: "4.6.4" }`, a `metadata` entry naming the ATLAS data version. The per-technique `tactic` field is **omitted** — ATLAS v6 carries no technique→tactic edge, the v4.5 layer format documents the field as optional, and the Navigator resolves placement from the matrix it loads.

```ts
// packages/cli/src/commands/coverage.ts
import { parseArgs } from 'node:util';
import { buildCoverage, formatCoverage, toNavigatorLayer } from '../coverage/report.js';

export async function runCoverageCommand(args: readonly string[]): Promise<number> {
  const { values } = parseArgs({
    args: [...args],
    options: { format: { type: 'string' }, json: { type: 'boolean', default: false } },
  });
  const report = buildCoverage();
  if (values.format === 'navigator') {
    process.stdout.write(`${JSON.stringify(toNavigatorLayer(report), null, 2)}\n`);
    return 0;
  }
  if (values.format !== undefined && values.format !== 'table') {
    process.stderr.write(`stroq coverage: unknown --format "${values.format}" (table, navigator)\n`);
    return 1;
  }
  process.stdout.write(
    values.json ? `${JSON.stringify(report, null, 2)}\n` : formatCoverage(report),
  );
  return 0;
}
```

## Self-review notes

**Spec coverage.** §5d — the vendored corpus (Task 1), `stroq bench` with `--corpus` (Task 2), the published number regenerated in CI (Task 6). §5e — the vendored denominator (already shipped by the previous plan), the scope declaration that makes the denominator honest (Task 3), the ASI layer pinned by edition (Task 4), the table with `covered | partial | not_covered` and limitations, uncovered items in the same summary line, a depth headline rather than a percentage, and `--format=navigator` (Task 5), and CI regeneration with a diff gate (Task 6). §8's public limits — the compliance-claim and not-an-audit sentences (Task 6 Step 3).

**One deliberate departure from the spec, argued where it is made.** §5e describes the vendored denominator as the whole denominator. Task 3 adds a scope declaration on top of it, because 197 ATLAS techniques include a great many a local hook-based firewall provably cannot address, and reporting against all of them would produce a number that is honest but useless — while silently reporting only what we cover would be the dishonest alternative. The scope file makes the choice explicit, complete and testable, which is the same instinct the spec applies everywhere else.

**Known risk this plan accepts.** The scope declaration is judgement, and judgement can be generous. The tests can prove it is complete and that its ids are real, but they cannot prove a technique belongs in scope or that a limitation string is adequate. That is why Task 5 Step 5 asks the implementer to read the finished table as a hostile reader, and why the branch's reviewer should treat any `covered` row backed by a single scenario as an overclaim until shown otherwise.

**Type consistency.** `loadAtlas`/`atlasIds`/`ATLAS_ID` come from the previous plan and are consumed here unchanged. `loadScope` is defined in Task 3 and consumed in Task 5. `loadAsi`/`asiIds` are defined in Task 4 and consumed in Tasks 4 and 5. `BenchReport`/`runBench`/`formatBench` are defined in Task 2 and consumed in Task 6. `CoverageReport`/`buildCoverage`/`formatCoverage`/`toNavigatorLayer` are defined in Task 5 and consumed in Task 6.

**What this plan does not do.** It changes no rule, no policy and no normaliser. If `stroq bench` reports a high false-positive rate, that is the measurement Part 4 exists to act on — §6a's `scan_target` scoping is the fix, and it belongs in Part 4's plan, not here. Lowering the number by editing rules inside this plan would destroy the before-and-after comparison the spec asks for.

# MCP cloak — design spec (2026-09-21)

**Goal.** `stroq init --agent mcp --cloak` makes the MCP stdio proxy replace values it can identify — the exact values of credentials this machine holds, plus structured PII — with stable placeholders on their way from a server's `tools/call` result to the model, and restore them on their way back to that same server. The model, and therefore the model provider, sees `[STROQ_EMAIL_1]`; the server keeps getting `peter@bugle.example`. Off by default.

**What this answers.** AgentCloak Desktop (InCountry, free, closed source) sits between a person and ChatGPT Desktop and does this for a human↔LLM chat: names, emails, phones, URLs, SSN/TIN, bank accounts and addresses become synthetic "digital twins", a local dictionary maps them back, a local model plus deterministic rules does the detection, EN + 6 languages. The full side-by-side — including every row where they are ahead of us — is `docs/CLOAK-COMPARISON.md`.

## 1. Why the MCP proxy, and only the MCP proxy

Stroq's other seven integrations are hook adapters, and a hook adapter **cannot** do this. Two independent reasons:

| Agent surface | Why not |
| --- | --- |
| Claude Code `PostToolUse` | Read-only. There is no field on the hook's answer that replaces a tool result, so a file's contents cannot be redacted before they enter the model's context. |
| `PreToolUse.updatedInput` (the tempting workaround) | **Corrupts user data.** Rewrite a `Read` of `.env` so the agent receives `[STROQ_EMAIL_1]`, and the agent's next `Edit` writes that placeholder into the real `.env`. AgentCloak does not have this problem because it owns the whole human→LLM→human channel; a coding agent runs arbitrary model behaviour between the read and the write, and nothing on the hook side gets to be in the middle of it. |

The MCP proxy is the one channel where Stroq owns both ends, and the loop closes safely because **a placeholder never touches a file**: it lives only inside the MCP conversation.

```text
server result → [cloak] → model sees [PERSON_1] → model emits tools/call using [PERSON_1] → [uncloak] → real value → server
```

This is not a consolation surface. An agent calling `mcp__slack__send_message` or `mcp__github__create_issue`, or reading 400 customer rows out of a database MCP server, sends all of it to the model provider **and** to a third party.

## 2. Detection — deterministic only

| Source | What it finds | Offsets | Restorable |
| --- | --- | --- | --- |
| `FileSecretIndex` (existing) | The **exact values** of credentials indexed from `.env*`, `~/.aws/credentials`, `~/.npmrc`, `~/.netrc`, `~/.docker/config.json` and credential-shaped environment variables | Located by literal search, in all four spellings `redactMatches` already rewrites | **No** — see §5 |
| `CLOAK_PATTERNS` (new, `packages/core/src/cloak/patterns.ts`) | `email`, `phone`, `iban`, `card`, `ssn` | `matchAll` against the original string | Yes |

Each pattern may carry a deterministic validator, which is what keeps the false-positive rate survivable: **Luhn** for a card, **ISO 13616 mod-97** for an IBAN, the **SSA allocation rules plus the ITIN carve-out** for an SSN, and **E.164's 7–15 digit window** for a phone. A candidate that fails its validator is dropped whole rather than retried shorter — a near-miss is an order number far more often than it is a mangled card.

**Out of v1, stated plainly:** person names and street addresses. They need NER; the credible offline option (GLiNER-PII via ONNX) would add this project's **first native runtime dependency**, which is the same reasoning that made `stroq run --sandbox` shell out to `srt` rather than link it in. `CloakDetector` in `cloak/types.ts` is the seam a later NER pass merges into (`cloak/detector.ts`). **Also out:** EIN/TIN in the `NN-NNNNNNN` form — it has no checksum, and the IRS campus-prefix list is the kind of table that goes stale inside a shipped binary, where a stale list is a silent miss. ITINs *are* covered, because they share the SSN shape.

**Why these are not ATR rules in `rules/`.** The plan suggested the existing YAML rule format, and it does not fit, for three reasons that each matter on their own:

1. `RuleMatch` carries **no offsets**, so nothing in the scanner's answer says where to cut.
2. The scanner deliberately fires on **decoded variants** (base64, hex, url) via `expandVariants`. A match found in a variant has no position in the original string at all. This is precisely why the engine's own `redactMatches` brute-forces every spelling rather than using positions.
3. An email address is **not instruction-like text**. `rules/` feeds `scanContent`, whose verdict taints the session — so a PII rule there would taint every session that reads a mailing list.

So the pattern table is a small declarative structure in TypeScript, next to the validators it needs, and the scanner corpus is untouched.

## 3. The offsets problem, and how it was resolved

Substitution needs spans, and a wrong span corrupts the payload rather than protecting it. The rule adopted everywhere in `packages/core/src/cloak/`:

> **A value is cloaked only where it was actually located in the exact string being rewritten. A value that cannot be placed is not cloaked at all.**

Concretely:

- **Patterns** run with `matchAll` against the original string, never a normalized or decoded variant. `m.index` is a real offset by construction.
- **Secrets** reuse the multi-spelling approach from `redactMatches` — `raw`, the decoded `token`, `encodeURIComponent(token)`, and that with lowercase hex escapes — but `secretSpans` records the positions `indexOf` really returns instead of rewriting blind. `SecretMatch.raw` is by construction a substring of the text the candidates came from, so the ordinary case always places; the other spellings may not, and when they do not, no span is emitted.
- **Merging** (`mergeSpans`) lays secrets down first and lets pattern spans fill only the gaps, so a credential always wins an overlap with a shape. Among patterns, earlier start wins, then longer, then table order (`ssn` before `phone`, so `123-45-6789` is an SSN).
- **Rewriting** (`applySpans`) walks the span list **right to left**, so every offset still describes the string it was found in. A left-to-right pass would shift each later span by the accumulated length difference — the exact bug class this feature has to rule out. `cloak-substitute.test.ts` pins it with placeholders longer than the values they replace, so a regression is visible rather than subtle.
- **Where the offsets live.** Detection and substitution run over the **string leaves of the parsed JSON**, not over the serialised line (`cloak/json-strings.ts`). Matching a line would mean matching against JSON's own escaping (`\"`, `\n`, `é`), where offsets no longer line up with the characters the model reads.

Object **keys** are never rewritten: a key is schema, and a rewritten key is one the server can no longer look up. A *secret* placeholder hidden in a key is still **found**, because `planUncloak` searches the serialised message — it just refuses the call rather than resolving it.

## 4. The dictionary — `~/.stroq/cloak/<key>.json`

The README says Stroq never stores a secret value, and that stays true of everything it stored before: the secret index holds `sha256(salt + value)`, provenance holds a redacted 120-character excerpt, the audit log runs every summary through `redact()`. A dictionary that can restore a value is a different threat model, so it is a different file with its own rules.

| Property | Value | Why |
| --- | --- | --- |
| Path | `~/.stroq/cloak/<sha256(session \n server)[0:16]>.json` | Its own directory, never `secrets.json`. `rm -rf ~/.stroq/cloak` is the one-command kill switch, and it cannot be confused with the one-way stores. |
| Mode | `0600` file inside a `0700` directory | Same as every other store; asserted in `cloak-store.test.ts`, because here it is a contract rather than hygiene. |
| Opt-in | `--cloak`, absent by default | No dictionary exists unless it was asked for. |
| Scope | **Per (session, server)**, not per session | The session is shared across a client's servers so a poisoned result from A taints calls to B — that is the point of it. A *reversible* dictionary shared the same way would let a placeholder minted from A's data, echoed into a call to B, be restored **into B**. Splitting it makes that impossible by construction: B has never heard of the placeholder, so the literal text travels. |
| Lifetime | `CLOAK_TTL_MS` = 12 idle hours, refreshed on every mint and every restore; pruned on the next read | "Scoped to the life of a session." Long enough that a conversation paused over lunch still resolves; short enough that a laptop stolen the next day carries nothing. |
| Cap | `MAX_CLOAK_ENTRIES` = 2000, least-recently-used dropped | Without it, one `SELECT * FROM customers` writes an unbounded copy of the table to disk. |
| Numbering | one monotonic `nextSeq`, never reset by pruning | A sequence number is never handed to a second value while the first may still be in a model's context. |
| Collision | a minted placeholder is checked against **both** the dictionary and the whole serialised result | A placeholder the server itself wrote would otherwise be resolved on the way back out into a value the server never sent. |
| Machinery | `withLock`, write-to-temp-then-`rename`, self-healing on an unreadable file — all reused from `secrets/index.ts` | Several proxies of one client run at once. The **one-way hash is deliberately not reused**: it cannot restore. |

**The self-healing direction matters.** A lost, expired or corrupt dictionary means a placeholder is forwarded to the server as literal text — never that the wrong value is restored. `lookup` reads without the lock (the common case is a call with no placeholder at all) and takes the lock only to refresh `at`; a failure there costs an early expiry, never a wrong answer.

## 5. Secrets are cloaked but never restored

This is the load-bearing asymmetry, and it is what makes the whole ordering safe.

A `[STROQ_SECRET_n]` placeholder stands for the value of a credential **this machine holds**. The model only ever saw the placeholder. Restoring it on an outbound call would be Stroq itself putting a credential on the wire — the exact action `deny-secret-egress` exists to stop. So:

- On the way **in**, a known secret value in a result is replaced, like anything else. That is new protection: the pre-existing egress guard watches arguments leaving, and has never been able to see a credential arriving in a server's *result*.
- On the way **out**, a call carrying such a placeholder is **denied**, `mcp-cloak-secret-restore`, with the credential named the way `deny-secret-egress` names it (`NAME (source)`) and never its value. `UncloakPlan.refused` carries **labels only** — the plan reaches a deny reason, an audit summary and, on a bad day, a stack trace, so the value is classified and dropped inside `planUncloak`.

## 6. Ordering: judge the cloaked call, then restore

The proxy judges the `tools/call` **as the model sent it**, placeholders and all, and substitutes only on the line it forwards.

That is safe because of §5 plus the kinds v1 restores. An email, a phone number, an IBAN, a card number and an SSN contribute **no `ActionClass`** (`classify-tool.ts` reads tool names and argument shapes, not these) and **no provenance atom** (`AtomKind` is `url | host | pkg | pipe_shell | encoded`). So restoring one after the decision cannot turn an allow into something the policy would have denied. Anything that *did* carry classification weight — a URL, a hostname, a package name — would have to be judged after restoring instead, and that is the constraint any future detector has to satisfy before it is added. The constraint is written at the top of `packages/cli/src/mcp/cloak.ts`, where the next person will be standing.

The refusal in §5 runs **before** the engine, because it is a hard refusal that does not depend on the policy.

## 7. Byte-exact forwarding

`framing.ts:3-9` documents that an allowed line reaches the other side as the bytes that arrived. Cloaking breaks that on two paths, and the note at the top of `framing.ts` now says so where the invariant is stated:

| Path | Re-serialised? |
| --- | --- |
| A suspect `tools/call` result (`withWarningBlock`, pre-existing) | Yes — the precedent that proved response-side rewriting is accepted by real clients |
| A **cloaked** `tools/call` result | Yes, under `--cloak` only |
| A `tools/call` request whose placeholders were **restored** | Yes, under `--cloak` only |
| A message the cloak did not change | **No** — still byte for byte, `--cloak` on or off |

That last row is enforced, not aspirational: `forwardWithRestores` returns the original `SplitLine` when `plan.values.size === 0`, and the pump only builds a reply object when a cloak or a warning actually produced one. `proxy-cloak.test.ts` pins the clean-result line character for character with the flag on.

`PendingTable` (`framing.ts:239-291`) is the request↔response join the dictionary needed; it was already there and is unchanged.

## 8. Oversize and unscannable results

`proxy-pump.ts` forwards a server line above `MAX_LINE_CHARS` (8 MiB) unparsed. With `--cloak` on, forwarding it would deliver in full exactly the values the cloak was switched on to withhold, so:

- **Oversize (never parsed).** Every segment of the run is **dropped**, logged once, and audited once as `mcp-cloak-unscannable-result`. The client's request for it goes unanswered — which costs exactly what a server that never replied would cost, and a hostile server can already do that at will. Recovering the request id from a bounded prefix so a synthetic error can be sent instead is the follow-up.
- **Parsed but too large.** A result that serialises past `MAX_CLOAK_CHARS` (2 MiB — the same bound the secret-egress guard reads to, deliberately the same number) is refused by `cloakResult` and dropped the same way. Cloaking a prefix would deliver the uncloaked remainder, which is worse than not cloaking.

Both are tested (`proxy-cloak.test.ts`, "drops an oversize result rather than delivering it uncloaked").

## 9. Audit

Every substitution is in the hash-chained log, **kind and placeholder only, never the value** — `CloakEvent` in `audit/audit-log.ts` has no field that could hold one.

```text
#3  post mcp__crm__get_customer [hand:1] cloak(cloak)   mcp cloak: 3 value(s) replaced in a tools/call result {email:[STROQ_EMAIL_1]×2 card:[STROQ_CARD_2]×1 ssn:[STROQ_SSN_3]×1}
#5  pre  mcp__crm__send_message [hand:1] cloak(uncloak) mcp uncloak: 1 placeholder(s) restored, 1 unresolved and forwarded as written {email:[STROQ_EMAIL_1]×1}
#11 pre  mcp__crm__send_message [hand:1] deny(mcp-cloak-secret-restore) mcp cloak: tools/call carrying a secret placeholder (DEMO_API_KEY (…/.env))
```

A cloak entry has neither a decision nor a scan, which used to print as `-(0.00)` — "nothing happened" for the one line saying a value was replaced. `formatEntry` names the direction instead.

## 10. Surface

- `stroq mcp … --cloak` — a bare flag, parsed out of the value-taking options so `--cloak --pass-env T` still reads `T` as `--pass-env`'s value. Never read from after `--`, where it belongs to the server.
- `stroq init --agent mcp --client <c> --cloak` — writes `--cloak` into each wrapper after `--pass-env` and before `--`. `wrapperIndex` keys on `mcp --server <name> --client` and `unwrapArgs` reads from the separator, so neither notices. Re-running `init` **without** the flag takes it back off, rather than leaving a reversible dictionary running because it was once switched on. A four-line note prints only when the flag was used.
- `packages/cli/src/mcp/cloak.ts` (façade), `cloak-factory.ts` (wiring: real index, real audit log, per-server dictionary path).
- Core: `packages/core/src/cloak/{types,patterns,substitute,secret-spans,json-strings,detector,store}.ts`; `candidatesFromText` split out of `candidateTokens` in `secrets/candidates.ts`; `CloakEvent` added to `audit/audit-log.ts`.

## 11. Limits to state in the README

- **Names and street addresses are not detected.** The one thing AgentCloak does that this does not, and the demo shows it: `Peter Parker` survives a cloaked result with his email, phone, card and SSN all replaced.
- **`tools/call` results only.** `tools/list` is a schema the client caches and validates against; `resources/read` and `prompts/get` are not rewritten in v1.
- **Object keys are not rewritten** (a secret placeholder in one still refuses the call).
- **A result above 8 MiB, or above 2 MiB once parsed, is dropped, not forwarded.** The client's request for it goes unanswered.
- **A secret placeholder blocks the call** rather than resolving.
- **An expired, pruned or unknown placeholder is forwarded literally** — the server receives `[STROQ_EMAIL_9]` as text.
- **The dictionary holds values in the clear** under `~/.stroq/cloak` for up to 12 idle hours, `0600`. `SECURITY.md` has its own section on it.
- **Per-server dictionaries mean no cross-server restore** — deliberate, and the safe direction.
- **The cloak cannot help a model that never echoes the placeholder.** It is text the model must reproduce; a model that paraphrases it loses the link, and the call goes out with a broken placeholder rather than a value.
- **No `ask`**, as everywhere else in the proxy.

## 12. Out of scope (v1)

NER for names and addresses; non-English pattern sets (AgentCloak does 6 more languages); `tools/list`/`resources/read`/`prompts/get` cloaking; object keys; a `stroq cloak` command to inspect or clear a dictionary; synthetic "digital twins" (a realistic fake name rather than a bracketed token — see the comparison doc for why a token is the right call for an agent and the wrong one for a human); hook adapters (§1).

## 13. Test strategy

Core, pure: pattern spans asserted as `text.slice(start, end)` on every case (never "did it match"), Luhn/mod-97/SSN/E.164 validators both ways, no-overlap and repeated-value invariants, `mergeSpans` precedence, right-to-left substitution pinned with longer placeholders, `collectStrings`/`mapStrings` depth bound and key immunity, `secretSpans` placing every spelling and reporting **nothing** for a value it cannot place, `candidatesFromText` agreeing with `candidateTokens`.

Core, I/O: `FileCloakStore` mint stability, mode `0600`, collision avoidance against the text, TTL expiry and refresh, monotonic sequence across pruning, LRU cap, corrupt-file self-heal, and inertness with no requests.

CLI unit: `McpCloak` with a hand-written detector — every leaf rewritten, `unchanged`/`refused` outcomes, the audit carrying no value, the round trip, an unknown placeholder left alone, a secret placeholder refused (and the plan asserted not to contain the value), a secret placeholder in a key.

CLI integration, through the real `runMcpProxy` against the real stdio stub: PII replaced in text *and* `structuredContent`, the notice block, the audit, the round trip proved by reading what the **server** received, an unresolved placeholder forwarded literally, the secret refusal with the server log proving nothing was forwarded, the oversize drop, and a clean result still byte-exact. Plus `--cloak` off behaving exactly as before.

Argv/installer: the bare flag, its interaction with value-taking options, its absence after `--`, the wrapper shape, and that a wrapper written with it is still recognised and is un-cloaked by a plain re-`init`.

Demo: `examples/demo/run-mcp-demo.sh` scenarios 7 and 8, asserted with `grep`, including that the audit contains the placeholders and neither the email nor the SSN.

# Windsurf adapter — design spec (2026-09-06)

**Goal.** `stroq init --agent windsurf` gives Windsurf's agent, Cascade, the protection Claude Code, Cursor, Codex, Copilot CLI and OpenClaw have — content scan + session taint, provenance, secret egress guard, ordered policy, hash-chained audit — through Cascade Hooks, offline, fail-closed wherever Windsurf allows.

**Sources (fetched 2026-09-06).** Official: `docs.windsurf.com/windsurf/cascade/hooks` (the whole contract: locations, file shape, the twelve events and their `tool_info` payloads, exit codes; read from `docs.windsurf.com/llms-full.txt`, the markdown the HTML page is rendered from). Cross-checked with four third-party integrations that read the same payloads: `sheeki03/tirith` (`pre_run_command`, `tool_info.command_line`, exit 2 = block), `open-gsd/gsd-core` (`hooks/gsd-windsurf-pre-command.js`: the full envelope — `agent_action_name`, `trajectory_id`, `execution_id`, `timestamp`, `model_name`, `tool_info`; "no stdout contract"; exit 2 with the reason on stderr; any other failure fails open), `apache/casbin-gateway` (`agenthook/windsurf.go`: every event's `tool_info` fields, `trajectory_id` as the session key) and `zscaler/zguard-ai-integrations` (`pre_mcp_tool_use`, fail-closed via exit 2). All four agree with the docs; none shows a field the docs omit.

## 1. What Windsurf gives us

| Item | Contract |
| --- | --- |
| Locations | System: `/Library/Application Support/Windsurf/hooks.json` (macOS), `/etc/windsurf/hooks.json` (Linux/WSL), `C:\ProgramData\Windsurf\hooks.json`. User: `~/.codeium/windsurf/hooks.json` (Windsurf IDE), `~/.codeium/hooks.json` (JetBrains plugin). Workspace: `.windsurf/hooks.json`. **One file per level, merged system → user → workspace** — there is no per-file loading, so Stroq's entries share the file with the user's own and `init` must merge, the way it does for Cursor's `.cursor/hooks.json`. |
| File shape | `{ "hooks": { "<event>": [ { "command": "<sh command>", "powershell"?: "<pwsh command>", "show_output"?: boolean, "working_directory"?: string } ] } }`. `command` runs via `bash -c` on macOS/Linux; `powershell` via `powershell -Command` on Windows (falls back to `command`). No `version` key, no `matcher`, **no timeout parameter**. `working_directory` defaults to the workspace root (in a multi-repo workspace, the root of the repo being worked on); `~` is not expanded. |
| Events | `pre_read_code`, `post_read_code`, `pre_write_code`, `post_write_code`, `pre_run_command`, `post_run_command`, `pre_mcp_tool_use`, `post_mcp_tool_use`, `pre_user_prompt`, `post_cascade_response`, `post_cascade_response_with_transcript`, `post_setup_worktree`. Only the five `pre_*` events can block. |
| stdin (every event) | `{ agent_action_name: string, trajectory_id: string (the conversation), execution_id: string (the turn), timestamp: string (ISO 8601), model_name: string, tool_info: object }`. **The event name is in the payload**, so one command serves every event. |
| `tool_info` per event | `pre_read_code`/`post_read_code`: `{ file_path }` (may be a directory when Cascade reads recursively; the file's CONTENT is not in the payload). `pre_write_code`/`post_write_code`: `{ file_path, edits: [{ old_string, new_string }] }`. `pre_run_command`/`post_run_command`: `{ command_line, cwd }` (the command's OUTPUT is not in the payload, not even on `post`). `pre_mcp_tool_use`: `{ mcp_server_name, mcp_tool_name, mcp_tool_arguments: object }`. `post_mcp_tool_use`: the same plus `mcp_result: string`. `pre_user_prompt`: `{ user_prompt }`. `post_cascade_response`: `{ response }` (markdown of Cascade's whole turn). `…_with_transcript`: `{ transcript_path }` (JSONL, `0600`, written asynchronously). `post_setup_worktree`: `{ worktree_path, root_workspace_path }`. |
| Exit codes | `0`: the action proceeds. `2`: **the Cascade agent sees the message on stderr; on a `pre_*` event the action is blocked.** Any other exit: the action proceeds (**fail-open**). There is no stdout contract and no `ask`. With `show_output: true` the user also sees the hook's stdout/stderr in the Cascade UI. |
| Timeout | Undocumented. There is no configurable budget and no statement of what a hung hook does. |

## 2. Adapter contract (`packages/cli/src/adapters/windsurf.ts`, input helpers in `windsurf-input.ts`)

- **Events Stroq installs on — exactly six:** `pre_read_code`, `post_read_code`, `pre_write_code`, `pre_run_command`, `pre_mcp_tool_use`, `post_mcp_tool_use`. Not installed, each for a stated reason: `post_write_code` (Cascade wrote the content; there is nothing untrusted to scan), `post_run_command` (the payload carries `command_line` and `cwd` only — no output — so a hook there is a Node start per command that can scan nothing), `pre_user_prompt` (the user's own words are not Stroq's to police), `post_cascade_response` and `…_with_transcript` (the model's own text, delivered asynchronously; a follow-up, see §3), `post_setup_worktree`. `stroq hook windsurf` still answers an event it did not install on — any other `agent_action_name`, including future ones — with exit 0 and no output: Stroq does not block what it does not understand, and blocking `pre_user_prompt` by accident would block the user.
- **One command for every event:** `"<node>" "<entry>" hook windsurf` — no phase argument, because `agent_action_name` names the event (`commands/hook.ts`'s entry has no `checkArg`; `hookCommand(node, entry, 'windsurf')` as for Claude Code, Cursor and Codex). `stroq init` recognises its own entries by the command suffix ` hook windsurf` (`isStroqWindsurfHook`).
- `WindsurfHookInputSchema`: zod `looseObject` — `agent_action_name: string` (required; a payload without it is malformed, and malformed input is fail-closed, not ignored), `trajectory_id: string.min(1)` (the session id; documented as present on every event), `tool_info: unknown` optional (an object; tolerant of a JSON string through `toolInputRecord`), `execution_id`, `timestamp`, `model_name` optional unknown (never rejected).
- **Working directory for policy = the hook process's own `process.cwd()`**, which Windsurf sets to the workspace root (`working_directory`'s default), and never `tool_info.cwd`: that field is the directory Cascade chose for the command, i.e. model-controlled, and honouring it would let a tool call point the secret index and path classification at an empty directory — the OpenClaw adapter's Critical, corrected before ship. `tool_info.cwd` is not read at all for a shell call: the shared reader reduces the call to `{ command }`, exactly as it does OpenClaw's `exec`, so nothing strips it as a hostile field and nothing ever uses it (post-plan amendment: the earlier wording said it stayed in the record for the audit, which the shared `kindToolInput` does not do, and an unshared copy of a shared security reader is not worth one inert audit field).
- Tool-name and input mapping (`windsurfToolName`, `windsurfToolInput`, by `agent_action_name`):
  - `pre_read_code` / `post_read_code` → `Read`, kind `read`: the record is `tool_info` with `file_path` from `pathsOf` (every distinct non-empty candidate among `file_path`, `path` and `raw` — Windsurf spells it `file_path`, the same key core reads; the others are the shared robustness rule), `file_paths` when the candidates disagreed (fan-out through the shared `preCandidatesFor`/`preInputs`, worst decision wins).
  - `pre_write_code` → `Edit` when `edits` is a non-empty array, else `Write` (the two classify identically in core; the split is for the audit's readability), kind `write`: `file_path` by the same rule, `edits` kept in the record. A `pre_write_code` whose non-empty `tool_info` yields no path is denied as `windsurf-unreadable-input` (the shared `unreadableGuard`), never written unexamined.
  - `pre_run_command` → `Bash`, kind `shell`: `{ command }` through the shared `commandCandidates`/`commandOf` (`codex-input.ts`), whose spelling list **gains `command_line`** — Windsurf's documented key — so every agent's reader accepts it (one list, one fix); every spelling present is a candidate, not the first. Non-empty `tool_info` with no readable command → `windsurf-unreadable-input`.
  - `pre_mcp_tool_use` / `post_mcp_tool_use` → `mcpToolName(mcp_server_name, mcp_tool_name)` = `mcp__<server>__<tool>` (`cursor-mcp-name.ts`: sanitised, hostile names cannot forge a separator; an absent server → `mcpToolName('windsurf', tool)`, an absent tool → the helper's `call` fallback), kind `mcp`: the record is `mcp_tool_arguments` as-is through `toolInputRecord` (object, JSON string, bare value → `raw`), never reduced, so the secret egress guard scans every field. Windsurf, unlike Copilot and OpenClaw, DOES report the server name, so rules keyed on a server work here.
- Engine calls: `pre` → the shared `decideWithGuards` (unreadable-input deny first, then `windsurf-too-many-targets` when a candidate list exceeds `MAX_PATCH_PATHS` = 64, then one `engine.pre` per candidate with the worst decision winning). `post_mcp_tool_use` → `engine.post` with `toolResultText = windsurfResultText(tool_info)`: `mcp_result` when it is a non-empty string, else `streamResultText`/`toolResultToText` over whatever `mcp_result` is. **`post_read_code` → Stroq reads the file itself**: the payload carries only the path, so `windsurfReadText(file_path, cwd)` reads at most `WINDSURF_MAX_READ_BYTES` (1 MiB) of it as UTF-8 (a relative path resolved against the policy cwd) and hands that to `engine.post` as the `Read` result; a directory, a missing or unreadable file, an empty path or an empty file scan nothing (exit 0, no output, no error — a read that gave Cascade nothing gave the model nothing either). The 1 MiB cap keeps a huge file from running the hook past whatever timeout Windsurf has; the scan itself is bounded by core.
- Output (there is no stdout contract; everything meaningful is exit code + stderr):
  - `pre` allow → `NO_OUTPUT` (exit 0). `pre` deny → **exit 2, stderr** `Stroq blocked this action (<rule>): <reason> Evidence: …`, stdout empty (`windsurfBlockOutput`). `pre` **ask → exit 2** with the Codex wording adapted: `Stroq would ask before this action (<rule>): <reason>. Windsurf hooks cannot prompt, so it is denied; run it yourself or relax the rule in ~/.stroq/policy.yaml.` — lossy on the wire by design, never in the audit, which records the policy's real `ask`.
  - `post` suspect → **exit 2 with the warning (`warningFor`) on stderr**: the documented channel by which "the Cascade agent will see the error message", and on a post-hook exit 2 blocks nothing because the action has already happened; clean or unscanned → `NO_OUTPUT`.
- Fail-closed (`windsurfFailClosedOutput`): an internal error on a **high-impact `pre` event** — `pre_run_command`, `pre_write_code`, `pre_mcp_tool_use` — answers exit 2 with `Stroq internal error (fail-closed): <message>` on stderr; `pre_read_code` answers `NO_OUTPUT` (the same trade-off Claude Code, Codex, Copilot and OpenClaw make for their read tools: a tainted read of `.env` is a real deny that this fails open on, and stalling the agent on every failed read buys less than it costs); every `post_*` and every unknown event answers `NO_OUTPUT`. A missing or non-string `agent_action_name` is malformed and answers exit 2. stdin that is not JSON, or a stdin read that rejects (`stdinFailClosed: true`), answers exit 2 for every event: with no event to inspect, exit 2 is a deny on a pre-hook and a visible message on a post-hook, the smallest harm available. Any exit other than 0 or 2 is an allow on Windsurf, so the adapter never exits 1 on purpose.
- `stroq hook windsurf` joins `commands/hook.ts`'s table (`handle`, `failClosed`, `badJson: windsurfBlockOutput`, `stdinFailClosed: true`, no `checkArg`); `SUPPORTED_AGENTS` and `init`'s `HOOK_AGENTS` gain `windsurf`; `index.ts` usage text.
- `stroq init --agent windsurf` (`commands/windsurf-hooks.ts`): merges into `<workspace>/.windsurf/hooks.json` (default) or `~/.codeium/windsurf/hooks.json` (`--user`), Cursor-style: read the file (absent → `{}`), for each of the six events drop every existing Stroq entry (`isStroqWindsurfHook`) and append `{ command: '<hookCommand>', powershell: '& <hookCommand>', show_output: true }`; every foreign entry, foreign event and other key is preserved untouched; write the merged object. `show_output: true` so the block reason and the taint warning are visible in the Cascade UI (on an allow Stroq prints nothing, so nothing shows). No `working_directory` (the default, the workspace root, is the trusted cwd the adapter relies on), no `version` (the format has none). `--dry-run` prints the merged JSON on stdout and writes nothing. Prints the note: restart Windsurf (or reload the window) if the hooks do not fire — the docs do not say when the file is read; hooks from the system, user and workspace files all run, in that order; `stroq init --agent windsurf --user` writes `~/.codeium/windsurf/hooks.json` instead; the JetBrains plugin reads `~/.codeium/hooks.json`, which `init` does not write (copy the entries there).
- `stroq doctor`: a `windsurf hooks` line (project `.windsurf/hooks.json` / user `~/.codeium/windsurf/hooks.json`, through the existing `agentScopes`); installed only when **all six** events carry a Stroq entry — a half-install is not partial protection (a `pre` without its `post` never taints, a `post` without its `pre` never blocks); `ok` when at least one agent is installed.
- Core change (the only one, as for every adapter): `SELF_CONFIG_FILE` gains `(\.windsurf|\.codeium(\/windsurf)?|etc\/windsurf|Windsurf)\/hooks\.json` — the workspace file, both user files, and the Linux and macOS system files (the capitalised `Windsurf` alternative matches the macOS `Application Support/Windsurf/hooks.json` path and nothing in the lowercase user paths) — and `PROTECTED_DIRS` gains `windsurf` and `codeium`, so a tainted session cannot edit, delete or `find … -delete` Stroq's hook file whether through `pre_run_command` (`config.self` in the Bash classifier) or `pre_write_code` (the Write/Edit path check). `.windsurf/rules/` and `.windsurf/workflows/` stay editable: the match is on `hooks.json`, not the directory, for the same reason the bare `.claude` match was narrowed.
- Docs: README "Supported today: Claude Code, Cursor, Codex, Copilot CLI, Windsurf (native hooks) · OpenClaw (in-process plugin)"; Install `--agent windsurf`; a `### Windsurf` subsection (event table, what taints and what cannot, limits); `packages/cli/README.md` the same; SECURITY.md scope; CHANGELOG; demo `examples/demo/windsurf-events/` + `run-windsurf-demo.sh` (the CLI adapter with Windsurf-shaped payloads, every decision asserted, only exit 2 = block, no secret value in any output: `post_read_code` of a poisoned README written by the script → taint; `pre_run_command` `curl … | sh` → blocked; `pre_run_command` `ls` → allowed; `pre_write_code` on `.windsurf/hooks.json` → `deny-self-tamper`; `pre_mcp_tool_use` with a `.env` value in `mcp_tool_arguments` → `deny-secret-egress`; `pre_run_command` `git reset --hard` → the "would ask" block; `post_mcp_tool_use` with a poisoned `mcp_result` → warning on stderr); CI step.

## 3. Limits to state in the README

- **No `ask`.** Cascade hooks can only allow or block; a policy `ask` is rendered as a block that names the rule and says how to proceed. The audit keeps the real `ask`.
- **Command output is invisible to hooks.** `post_run_command` carries the command line only, so a poisoned command output cannot taint a Windsurf session the way it taints Claude Code, Cursor, Codex or Copilot. Files Cascade reads (`post_read_code`, scanned by reading the file) and MCP results (`post_mcp_tool_use`) do taint. Web pages Cascade fetches have no hook event at all and cannot taint the session either.
- **No hook timeout setting**, and the docs do not say what a hung hook does. Stroq answers in well under a second; keep `@stroq/cli` installed globally so no `npx` download runs inside the hook.
- **Any exit other than 0 or 2 fails open** (Windsurf's contract). Stroq therefore answers its own internal errors on a high-impact `pre` event with exit 2.
- **A call naming more than 64 files is denied** (`windsurf-too-many-targets`) rather than classified one path at a time — the shared bound.
- The working directory used for policy is the hook's own (the workspace root), never the `cwd` a command names; a command run in another directory is still judged against this workspace's secret index.
- `pre_write_code`'s `edits` are recorded in the audit summary like any other tool input; the secret egress guard does not scan file writes (it guards egress), the same as for every other agent.
- The wire format is taken from Windsurf's documentation and four third-party integrations, not recorded from a session; fixtures are hand-written. Windows: a `powershell` entry is written but untested. System-level and JetBrains hook files are not written by `init`.

## 4. Out of scope (v1)

`post_run_command` (nothing to scan), `post_write_code`, `pre_user_prompt`, `post_cascade_response` and the transcript hook (a later adapter could scan the JSONL transcript for command outputs after each turn — too late for that turn, in time for the next), `post_setup_worktree`, the JetBrains and system-level files, Windsurf-shaped `stroq attack` scenarios (engine shared; e2e + demo cover the wire mapping).

## 5. Test strategy

Adapter unit tests with documented-shape payloads (every installed event; `tool_info` as object and as JSON string; `command_line` alone and beside `command`; `file_path` vs `path` disagreement; `edits` present/absent; MCP names including hostile ones — the invariant tests the Copilot and OpenClaw adapters carry; absent server; unknown and future event names → silent exit 0; missing `agent_action_name` → exit 2), `post_read_code` file reading against temp files (regular file, directory, missing, empty, oversized truncated at 1 MiB, relative path), decision tests on the real engine (taint through `post_read_code` then `curl | sh` → exit 2 `deny-encoded-exec`; self-tamper on `.windsurf/hooks.json` and `~/.codeium/windsurf/hooks.json` through both `pre_write_code` and `pre_run_command`; secret egress through `mcp_tool_arguments` and through `command_line`; `ask` → exit 2 with the "would ask" wording and a real `ask` in the audit; unreadable input; fail-closed exit 2 on the three high-impact pre events only; `post_mcp_tool_use` suspect → exit 2 warning; `tool_info.cwd` ignored for policy), table-driven shape test as in Codex/Copilot, installer tests (project/user paths, merge preserves foreign entries and events, idempotent re-run replaces rather than stacks, dry-run writes nothing, `show_output: true`, `powershell` line), doctor (all six / half-install / foreign file), core self-config tests for the new paths, e2e spawning the CLI with every event, demo in CI.

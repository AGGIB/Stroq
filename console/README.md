# Stroq console

The Stroq console is a private page on your own machine for checking whether your agents are protected, following what Stroq records, reviewing skills and MCP servers, and investigating activity. Start it with `npx @stroq/cli console [--workspace <dir>] [--port <n>]` and open the whole link it prints; from a source checkout, run `pnpm platform --workspace <dir>`. Diagnostics and content scans run on the actual Stroq engine, and the console keeps configuration evidence, policy simulations and live host verification separate.

**Agents & coverage** keeps each agent's Configure and Test actions together, with direct Codex network, path and skill controls. Details holds approval, exact recorded hook evidence, observations, offline checks and removal. Project and user scope stay explicit. A configured hook and a passing offline response do not establish native client enforcement.

Codex Network Guard: **Agents & coverage → Codex → Manage** previews an exact base user network setting, keeps Restore available, and separately runs fixed TCP/Unix sandbox canaries on an isolated permission copy without a model. Protection shows changed settings separately from historical check results, with exact record links. Checks preserve ownership across consoles; passive reads never repair unfinished attempts. See [scope, compatibility and retention](../docs/platform/codex-network-guard.md).

Codex File Guard: **Agents & coverage → Codex → Credential paths → Manage** explicitly inspects seven fixed credential-path presets and previews an exact read/write denial in an eligible existing named USER default profile. Restore preserves later unrelated settings and remains available after target removal. Credential targets use metadata only; native enforcement and current-chat adoption remain unverified, and File Guard has no native-check action. It does not migrate a built-in, implicit or legacy default profile. Its stored data and limits are under [Local data and limits](#local-data-and-limits).

**Codex sources → Disable this path** changes one exact captured SKILL.md declaration in the selected Codex data directory's base user configuration. **Saved changes → Preview restore** removes Stroq's own change while preserving later unrelated settings, even after source removal or restart. Shared-user/retention consent, separate Restore weakening consent and exact unknown-outcome recheck are explicit. Native adoption, named-profile/session overrides and already loaded instructions remain separate; normal reads never launch Codex. See [workflow and limits](../docs/platform/codex-skill-controls.md).

**Clear stored session taint** in Investigations inspects the exact finding's session and requires a fresh preview plus two explicit acknowledgements. It preserves provenance and the audit journal; independent restrictions and new input can still refuse actions. The native session lock, durable private backup and explicit recheck keep historical publication separate from current state. See [taint controls and retention](../docs/platform/session-taint.md).

**Make tasks manual** in Protection → Workspace changes only supported automatic triggers in the captured root `.vscode/tasks.json`. It preserves manual tasks, comments and mode, retains a complete private original copy and verifies the file with a new static capture. Restore requires its exact unchanged publication and separate consent. The selected Stroq home retains at most 32 recovery/staging entries within 8 MiB, without automatic eviction or expiry. No task, editor or provider is started. See [task controls and retention](../docs/platform/workspace-task-controls.md).

**Skills & MCP → Protect & review tools** explicitly adds the strict tool-contract gate to an eligible stdio entry. Reconnect its client, then open **MCP tool review** to inspect saved full definitions, approve exact versions or revoke future dispatch. The first baseline is pending; the entire complete listing is held until its advertised versions are approved. A client root discovery request can collect up to 16 pages through the already running server; opening or refreshing the console never probes it. Advertised metadata is stored privately but unencrypted. See [MCP tool-contract approval](../docs/platform/mcp-tool-contracts.md).

## Run

From the published package, `npx @stroq/cli console` starts the console for the current folder. `--workspace /path/to/repo` selects another project and `--port <n>` another local port (the default is 47815).

From a source checkout, the console requires Node.js 22+ and pnpm. Run from this directory:

```sh
pnpm install --ignore-workspace --frozen-lockfile
pnpm dev                 # http://127.0.0.1:47813 — synthetic demo
pnpm build               # local engine adapters + static export in out/
pnpm serve:local         # private loopback URL printed at startup
```

From the repository root, `pnpm platform:build` builds the core/CLI and platform; `pnpm platform --workspace /path/to/repo` starts it for a selected existing project. Install console dependencies separately with `pnpm --dir console install --ignore-workspace --frozen-lockfile` after the root frozen install. The selected workspace is named in the sidebar and setup previews.

Open the **full private URL** printed at startup. Its fragment token authenticates the browser without putting the token in HTTP request URLs. The browser removes the fragment and keeps the token in session storage. Settings can switch back to the example workspace; the example dataset is always labeled. The source server can be configured with `STROQ_CONSOLE_PORT` and `STROQ_HOME`.

Build the core and CLI from the repository root (`pnpm build`) before starting local checks. The server verifies that the built CLI version matches the package version. `pnpm serve:local` uses this repository as its workspace by default. Protection, Skills & MCP and active policy settings always operate on the local engine, independently of the example activity dataset. The home screen is Protection; Activity overview is at `/overview/`.

## What works

- Activity search, decision/agent/date/session filters and pagination; state survives reload in the URL.
- **Live:** the audit journal as it happens: a status line, counts of what was allowed, asked, denied and flagged, and a feed that adds new rows within about two seconds. Rows hold a coarse tool kind, action classes and a bundled rule id, never the command, path or reason, and a counts-only receipt you can copy. See [Live](../docs/platform/live-view.md); recorded decisions, not proof a host stopped anything.
- **Guide** (`/guide/`): which page to open for what and what to read on it, from the same map that groups the sidebar into Every day, Set up and When you need it (`console/lib/platform-map.ts`), and what the decision words mean.
- **Settings check:** reads the settings files of Claude Code, Codex, Cursor and Windsurf in your home folder and this workspace, and lists the settings that switch off or loosen protection: hooks off, run-without-asking modes, any-shell allow rules, a repository that redirects your prompts. Findings are ids from a fixed catalog, so no value from a file reaches the page. It also lists what it cannot see. See [Settings check](../docs/platform/posture-audit.md).
- **Try an action:** type one command, file read or write, or page fetch and see what your current policy would do, in a clean session and after the agent read untrusted text. The real engine judges a made-up event in throwaway folders; nothing runs, nothing is stored and the text is never returned. See [Try an action](../docs/platform/try-action.md); it is a recorded policy decision, not a test of any agent.
- Protection: **Run protection check** records installation, current-policy validation, bundled scenarios, separate Saved checks and an exact static workspace capture in one local attempt. Progress, owned cancellation, failures and stage links survive navigation/restart; individual checks remain available. See [Protection check](../docs/platform/protection-check.md); it is not native-host blocking proof. It uses no provider requests and does not change settings, policy, saved expectations, watches or review baselines.
- Workspace preflight: inspect startup and agent/editor execution surfaces, review a captured version and compare later checks with that baseline. Error attention remains after **Review this version**; partial captures preserve historical errors. Optional **Watch changes** repeats static checks every five minutes while the console service runs, feeding changes into Protection without approving versions. Source changes and detected capabilities remain separate; partial reads never establish removals or editor trust. Checks run without project commands or provider inference. See [workspace preflight](../docs/platform/workspace-preflight.md).
- [Recorded installation diagnostics](../docs/platform/installation-diagnostics.md) retain typed reasons and scope, distinguish absent agents from configured peers, and link supported issues to current settings/inventory. Legacy records stay readable without inventing details; a report never establishes current host health.
- [Isolated hook checks](../docs/platform/hook-checks.md): follow the exact setup receipt into a fresh source-bound preview, explicitly run two fixed events without an agent or provider request, and revisit durable result links. Cards and the protection queue keep the latest recorded attempt visible. Host enforcement remains untested by this workflow.
- [Task permissions](../docs/platform/task-permissions.md): page through signed Claude Code Task Lock records, open an exact permit beyond the first 64 archives, compare its issued policy with the current file and explicitly revoke it. Source-bound opaque cursors expire without silently replacing a page; no archive is automatically removed. [One-use access](../docs/platform/task-access.md) reviews fresh signed refusals before explicitly issuing a short extension and reads native consumption state. Issuance, gate evidence and host execution remain separate.
- A protection work queue derived from recorded setup gaps, policy failures and changed/unreviewed artifacts.
- Hook setup for Claude Code, Cursor and Codex (Windsurf is not offered: it became Devin, which reads other files): choose workspace/user scope, review a fixed-target preview, add missing exact templates and preserve unmatched registrations/settings. Only exact duplicates are removed; ambiguous commands remain visible as requiring review. Already-current sources are true no-ops. Changes require applicable shared-scope/full-copy consent and refuse stale previews. Codex requires approval in the host; installed hooks do not establish live blocking. See [connection and recovery](../docs/platform/agent-setup.md).
- Guarded hook removal: preview exact current-runtime hooks in the selected source, preserve other registrations, acknowledge weaker protection and full-copy retention, then inspect the receipt. Reconnect opens fresh setup. Running agents are not stopped; see [scope and recovery](../docs/platform/agent-disconnect.md).
- Skills from fixed Claude, shared agents, Codex, Cursor, Windsurf and Devin folders, plus supported JSON MCP configurations: source coverage, digest-bound rule matches, file fingerprints, static capabilities and explicit per-version reviews. Equal names from different origins remain distinct; filesystem presence does not prove a host loaded a skill. The review dialog compares captured files, capability counts and rule signals with the reviewed revision. Legacy and incomplete comparisons remain explicit. Artifact links bind workspace and version; exports retain the selected comparison. Refresh does not accept changes. Server programs are not launched.
- **Skills & MCP watch:** independently enable bounded static reads of the fixed project and personal sources every five minutes while the console runs. Observed versions retain derived changes and exact source/version links without advancing a reviewed baseline. Adjacent unchanged captures coalesce; new checks still refresh current attention. Pause retains history. See [source scope, retention and limits](../docs/platform/skills-mcp-watch-spec.md).
- **Codex sources:** manually inspect modern `.agents/skills` and legacy `.codex/skills` at the selected directory and bounded repository ancestors, plus user `.agents/skills` and the selected `CODEX_HOME/skills` root. Same-name copies retain their own family, scope and safe location; **User config** badges describe captured declarations, not session enablement. `CODEX_HOME` selects a data directory, not a named `--profile`; named profiles and session overrides remain uninspected. Static entrypoint evidence and explicit coverage gaps can be exported. Ordinary inventory, watches, review and recovery scopes stay unchanged. See [scope and workflow](../docs/platform/codex-skill-sources.md).
- Reversible skill quarantine for complete isolated direct or nested skill folders in all six fixed project/user sources: preview an exact SHA, move it outside discovery, recheck original/payload, and restore without replacing another installation. Original files remain private and unencrypted; current conversations retain loaded instructions. Overlapping skill entrypoints, synced/plugin/managed content and MCP sources are outside this folder action. See [scope and verification](../docs/platform/skill-quarantine.md).
- Reversible MCP registration removal for supported Claude Code project, Cursor project/user and macOS Claude Desktop manual JSON sources: preview one exact entry, preserve private recovery copies, recheck its source and restore only into a free slot while retaining newer siblings. Running servers and other sources are unaffected by this configuration operation. See [MCP scope and recovery](../docs/platform/mcp-containment.md).
- Exact-entry **Route through Stroq** configures the existing strict stdio proxy, with explicit policy/profile roots, shared user-context consent and exact-wrapper undo. Configuration/runtime evidence stays separate from a client's adoption or blocking proof. Known wrappers, unsafe environment overrides and remote transports are refused. See [MCP protection](../docs/platform/mcp-protection.md).
- [MCP launch-policy continuity](../docs/platform/mcp-policy-continuity.md): current proxies withhold new `tools/call` dispatch after parsed-policy changes or an unavailable source. Refusal remains latched until restart; restoring the file does not resume dispatch. Restart loads the current policy without automatically retrying calls. Older running proxies are not upgraded automatically.
- [MCP governance](../docs/platform/mcp-governance.md): capture supported registrations, select exact reported identities by channel, test the full replacement and apply a version 2 policy. Unlisted or unknown MCP calls are denied; listed calls continue through existing checks. History, exact-operation Recheck and whole-policy recovery keep write evidence separate from host adoption. This does not authenticate servers or pin registrations.
- Credential file filters in Claude/Cursor agent cards: inspect explicit rules and ownership, preview fixed additions, apply with source/scope/recovery consent, recheck and preview guarded undo through the shared harden engine. Git/main-checkout scope and preexisting user rules remain explicit; configuration is not live blocking proof. See [file filters](../docs/platform/credential-filters.md).
- Active policy settings: deny selected action categories, strengthen unmatched-action behavior, lower the detection threshold and promote approval rules to deny. Preview validates and replays the candidate against the current policy, lists ordinary-work interruptions, then requires explicit apply. Existing policy bytes are backed up.
- Recorded policy changes: inspect retained intent/backup metadata, test a prior version against the current policy and saved checks, then explicitly restore exact bytes or select the current bundled default. A new recovery copy and verified readback accompany restoration. See [tested policy recovery](../docs/platform/policy-recovery.md).
- Saved policy checks: capture an exact recorded class combination's current clean/suspect decisions, recheck them locally and gate every policy candidate using the same Stroq home across workspaces. Candidate mismatches prevent apply; shared-scope save and removal require explicit consent. See [saved-check workflow](../docs/platform/policy-workflow.md#saved-policy-checks).
- Skill review: paste or open a bounded text file, scan instructions or tool output, inspect rule matches and export a content-addressed report. No submitted content is executed or retained by the server.
- Global workspace search (⌘K / Ctrl+K), accessible dialogs and keyboard navigation.
- Event evidence, JSON export, and a personal review marker saved in this browser.
- Consistent overview metrics derived from the displayed dataset.
- Observed hooks, historical verification and explicit coverage gaps.
- Current configuration for three agents (Claude Code, Cursor and Codex) in workspace and user scope, including exact hook commands/options, separate approval requirements and machine-wide observations.
- [MCP call control](../docs/platform/mcp-call-control.md): configure an eligible stdio wrapper paused, then explicitly Pause/Resume new tool dispatch without rewriting its registration. Verified retained Setup records keep Pause available when the registration is no longer visible. Desired state, recorded refusals and native-client adoption remain separate.
- Explicit live blocking preview/start/cancel for measured host/platform combinations. At most 3–6 subscription requests; real, deny and control evidence are projected separately from installed workspace configuration. Browser reads never start a live check.
- Recorded investigations: policy denies, approval requests and content findings; manual review binds exact evidence, and full captured-journal verification uses the core hash-chain verifier.
- Explicit finding-to-permission lookup verifies the exact journal record and current signed workspace permit. The handoff binds the current permit revision and returns to the source finding; historical permit attribution and incident resolution remain unverified. See [task permissions](../docs/platform/task-permissions.md#from-a-finding-to-its-current-permission).
- Current-policy comparison for a selected policy finding uses the real evaluator under both taint assumptions; the original taint/policy version and host outcome were not recorded. Stable local links retain the record/filter, and individual exports bind evidence and captured comparison fingerprints.
- [Recorded evidence and exact Activity handoff](../docs/platform/recorded-evidence.md) show finite historical classes, origin matches/gaps, task-scope kind and scan/trust evidence. Activity uses raw-line digests to open the authoritative finding; local browser-only review is retired without migration. Missing, partial and unavailable evidence remain distinct from a recorded empty list. This read starts no model, native client or command and does not recover missing historical taint/policy or prove host blocking.
- [Local operator assessments](../docs/platform/incident-assessments.md) retain a finite outcome/reason and append history for an exact journal finding. Explicit recheck resolves unknown saves without replay; Protection keeps marked issues, reopened and unassessed findings in attention independently of Reviewed. Assessment does not change policy, trust, taint, permits, journal evidence or native state. The selected-home journal is shared across workspaces; historical workspace/actor attribution is unavailable.
- Secret exposure: explicitly preview and authorize a comparison of available local credential values with related workspace sessions, cancel a running scan, inspect bounded derived reports and export them. Page loads and report refreshes never start a scan.
- Searchable bundled rule reference at `/policies/reference/`, separate from the active policy.
- Dark, light and system themes; mobile navigation; reduced motion.

## Local data and limits

File Guard reads credential-path metadata only after explicit **Inspect settings** or Guard preview; passive saved-history reads and Restore inspect configuration without reading those targets. One-use previews expire after two minutes, with at most eight private plans / 8 MiB. Shared-user/full-config-retention consent precedes Apply; Restore has separate weakening consent. Complete original/candidate configuration copies remain unencrypted under `<selected-user-home>/.stroq/codex-path-guard/` with `0700` directories / `0600` files, independently of `STROQ_HOME`, capped at 32 records / 17 MiB including staging/reserve and without automatic expiry or eviction. These configuration copies can contain embedded credentials. Exact recheck never retries an unknown write; ownership and dependency conflicts refuse Restore.

Offline-check history is private, unencrypted and bounded to 32 runs / 8 MiB, without automatic expiry. All five check kinds share exclusive workspace ownership and verified durable publication. Parent reports retain typed diagnostics, finite results, fixed saved action classes, case IDs/revision and exact capture references rather than raw commands, policy YAML or subprocess output. Workspace captures retain their separate existing bounds; an unavailable selected run never silently opens a newer capture. See [scope and cancellation](../docs/platform/protection-check.md) and [queue boundaries](../docs/platform/engine-capabilities.md#offline-control-service).

`/api/snapshot` projects a bounded tail of `~/.stroq/audit.jsonl`, supported `last-hook` stamps, and historical `live` proofs. It reads no credential files or cloak dictionaries, returns no raw commands or tool content, and hashes session identifiers. Host attribution is not present in the audit schema and is shown as unknown. A policy deny is not proof that a host stopped an action. Historical verification is not presented as current protection.

Credential filter GET/preview reads only the three fixed configuration sources, shared harden manifest and referenced recovery inputs; it does not read the credential files named by the patterns. Plans are single-use, expire after two minutes and are bounded to eight private in-memory previews / 8 MiB total. The parent holds the existing engine manifest lock through worker termination. Actual source copies remain separately under `<STROQ_HOME>/backups/`, including after undo; credential-shaped settings use surgical recovery instead. These native filters are not an OS sandbox. See [source and retention details](../docs/platform/credential-filters.md).

Secret exposure uses the existing `stroq sent` matcher and provenance classifier in a separate bounded process. After a two-minute, single-use preview and explicit credential-read acknowledgement, it reads known home credential files, environment values, workspace/related session folders and their project ancestor `.env` files, registered canary targets, local MCP/Git metadata and referenced saved outputs. Credential symlinks and recorded paths may resolve beyond the selected workspace; the selected session scope is not a filesystem sandbox. Cursor discovery reads its store before project filtering. The process has a two-minute deadline, 256MiB heap cap, bounded output and cancellation; the Cursor SQLite preflight refuses oversized, corrupt or computed stores before the all-rows reader. No shell commands, provider requests or LLM inference are launched by a credential comparison.

Only fixed provider/source/route labels, counts and timestamps leave that process. Names, source paths, destinations, transcript IDs and credential values are withheld. At most eight derived jobs and 200 finding details per report are held in server memory; they disappear on restart. External routes, uncertain destinations, session visibility, provider routes and textual stop claims stay distinct. A recorded external route is not proof of receipt; a textual stop is not verified enforcement. Missing/rotated/encoded values, unsupported agents, archived/custom-layout Codex sessions and incomplete reads remain limitations. No matches is not a clean bill of health.

Operations the console does not support keep their terminal commands. Team accounts and remote fleets are outside this local console.

Live proof uses the existing official Claude/Codex drivers and verifier in an isolated project. Preview detects the host version without inference; start requires the exact preview, unchanged policy/runtime/host context and explicit subscription acknowledgement. Claude is driven on measured POSIX platforms; Codex is measured on Windows. Other combinations remain unsupported. The console's start and cancel path has been tested only with stand-ins, not with real host requests, and a stand-in cannot produce a verified live result. Offline historical proof reads do not establish the current host version. Running job history is bounded in memory; the engine's authoritative last passing/failing proof remains in its existing store.

Investigation reviews acknowledge a recorded finding and do not establish remediation. Policy comparison uses captured known action classes with both null and suspect taint; it does not reclassify commands, scan original content or evaluate task gates, adapter guards or installed-host enforcement. It rechecks exact journal evidence and policy-file bytes before accepting the report. Journal verification applies to the displayed captured checksum/time, not to future appends. Internal hash consistency does not establish signed authenticity or detect a rewritten chain/tail truncation without an independent checkpoint.

From a comparison, **Draft action controls** opens the exact event's workspace-bound policy view. Loading its action categories and preparing a preview are separate explicit actions. Category Deny controls cover every session context for all agents using this Stroq directory; preview discloses replaced/narrowed rules and real attack/ordinary-work impact. Scope and interruption acknowledgements are independent. Apply keeps a private backup, verifies the candidate receipt and rechecks current policy; **Recompare event** returns to the same finding without marking it resolved. See [policy controls](../docs/platform/policy-workflow.md).

**Save regression check** preserves the comparison's exact current decisions for both session-taint assumptions. The server reselects the immutable evidence and derives the classes/effects; the browser supplies neither. `/policies/checks/` and its refresh perform only local class evaluation. These expectations are shared by all candidates using this Stroq home, independently of workspace selection. Preview/apply bind the check-store revision, and any mismatched expectation blocks apply even when the bundled scenarios pass. Current-policy results and candidate results remain separate; neither establishes host adoption, live blocking or remediation.

Saved checks persist privately in `<STROQ_HOME>/console/policy-cases.json`, retaining fixed classes, expected effects, timestamps and source fingerprints without raw commands, content or credentials. They survive restart with no automatic expiry or eviction, up to 64 checks. Explicit removal acknowledges the weaker gate and shared scope. Identical expectations preserve their first source; conflicting expectations for the same class set require removal first. Unavailable storage is not an empty passing result. See [retention and security limits](../SECURITY.md#local-data-retention).

Hook setup currently requires macOS/Linux and the default user Stroq directory. Runtime paths must remain available after installation. Setup previews hold private candidates in memory for five minutes, bounded to eight plans / 8 MiB, and expose only the projected change summary. Changes retain complete prior configuration and advisory-record bytes under `~/.stroq/backups/console-setup/`, which may include credentials or unrelated settings, with no automatic expiry or eviction. Missing consent does not consume a preview. Already-current configuration writes no files or lock and does not adopt an installation record. See [connection and recovery](../docs/platform/agent-setup.md). Policy previews expire after ten minutes. Policy changes affect new hook invocations; MCP engines require restart, with current-runtime dispatch held by the continuity control above. Content review uses bundled rules with threshold 0.6, independently of the runtime policy setting.

Hook removal also requires POSIX and the default user Stroq home. Its five-minute, single-use previews remove only exact current-runtime registrations in one fixed source. Complete original settings and recovery metadata remain unencrypted under `<selected-user-home>/.stroq/backups/console-disconnect/`, with private permissions, no automatic expiry and a 32-record limit. User/home-alias scope needs separate consent. The writer shares the harden lock with native filters. Hook removal has not been tested against a real host. See [hook removal](../docs/platform/agent-disconnect.md).

The threat feed is off until Settings turns it on in a browser; then the server, never the page, downloads `https://pwn.watch/incidents.json` when the home screen asks (no redirects, at most 4 MiB, at most every 15 minutes, less often after failures) and compares it with a fixed list of project files and agent folders. See [threat feed](../docs/platform/threat-feed.md).

The server binds only `127.0.0.1`, requires a Bearer token for every API, rejects foreign Host/Origin/Fetch-Site headers, and refuses static path traversal and symlinks. `POST /api/runs` accepts five fixed diagnostic/content-scan actions; setup, policy, comparison and review routes have closed typed request shapes. Every action requires a same-origin bounded JSON request and accepts no executable, path or environment arguments. Diagnostic jobs run serially with deadlines, output caps and a separate scanner worker. The latest 32 derived runs persist privately under `<STROQ_HOME>/console/runs-<workspace-sha256>.json` using a workspace-bound version 2 envelope; legacy unscoped `runs.json` remains untouched and is not imported as current evidence. Jobs carry fingerprints of workspace identity, policy source bytes and runtime, observed before and after execution. Missing or changed bindings keep results historical. Current work-queue configuration comes from `/api/agents`, separately from doctor diagnostics. Opening another console or reading history never declares a retained worker stopped. Unowned unfinished checks remain state-unverified; only a new explicit admission under verified exclusive ownership can mark an earlier attempt interrupted. No check resumes on read. All five kinds require verified history publication before work and completion; storage failures remain visible, refuse new work and never overwrite malformed history. Raw CLI output and submitted text are not retained.

Reviewed inventory baselines are workspace-specific and contain only projected metadata and fingerprints. A review records a revision; it does not grant engine trust, pin a server or enable protection. Atomic writes recheck the previewed file identities and exact bytes. As with the CLI's existing hardening transactions, portable check/rename cannot provide an OS-level compare-and-swap against malicious processes running as the same user.

MCP configuration actions keep complete original and edited configuration files under `<selected-user-home>/.stroq/console/mcp-containment/`, including any embedded credentials and unrelated entries. This fixed user location is independent of a custom `STROQ_HOME`. New v2 records use `changed.json`; legacy v1 removals retain `removed.json` without migration. Retention is unencrypted, private (`0700` directories / `0600` files), capped at 32 records and 17 MiB, and has no automatic expiry or deletion after restore. Explicit preview acknowledgements precede a write. Windsurf/Devin and Windows mutation remain unsupported; rejected custom MCP config locations remain source-specific gaps. See [MCP containment](../docs/platform/mcp-containment.md).

The server serves a self-only Content Security Policy. Next's static bootstrap and styles currently require `unsafe-inline`; a nonce-based server is a separate hardening step. The token authenticates the browser against remote web origins, not against malicious processes running as the same OS user. A content scan with no detections does not certify a safe skill; a completed policy replay does not prove live blocking.

## Checks

```sh
pnpm typecheck
pnpm test                # filtering, command safety, snapshot validation
pnpm test:local          # real engine, HTTP journey, transactions, privacy and failure recovery
pnpm build
```

The fonts are bundled locally; their licence files are in `public/fonts`. Claude and Codex logos are the vendors' own app assets; Cursor and Windsurf logos are unmodified light/dark SVGs from their official brand kits. `public/brands/SOURCES.txt` records where each asset came from. The interface uses Radix primitives and Lucide icons.

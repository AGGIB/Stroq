How Stroq actually works.

Every hook event it installs on, the default policy, provenance and the secret egress guard, and every command. This is the reference; the front page is the pitch.

Overview

Coding agents read untrusted content constantly: web pages, file contents, MCP tool results, the output of commands they just ran themselves. When that content hides instructions, an agent that follows what it reads turns them into real actions — outbound requests, secret reads, external pushes, arbitrary shell.

Every guard in this field answers the same question: is the command in front of me dangerous? That question cannot be answered from the command alone. An npx that installs an attacker's package looks exactly like an npx that installs a dependency; what separates them is that one of them was dictated by something the agent had just read.

Stroq is built around that difference. It sits on the agent's own tool-call hooks, remembers what the session took in, and when an action matches something that arrived in untrusted output it says so by name: which file, which tool result, how long ago. stroq replay then reconstructs the whole chain for a session after the fact — including sessions that ran before Stroq was installed. No cloud round trip, no proxy, and no relying on the model to notice the injection itself.

Six agents and any MCP client, one engine. Native hooks for Claude Code, Cursor, Codex, Copilot CLI and Windsurf, an in-process plugin for OpenClaw, and a stdio proxy for any other MCP client (Claude Desktop included) — the same classifier, policy, taint and audit everywhere.

Install

npx @stroq/cli init                  # Claude Code: writes .claude/settings.json hooks
npx @stroq/cli doctor                # check the installation

init writes hooks into the project's .claude/settings.json by default; pass --user to install into ~/.claude/settings.json instead, or --dry-run to preview the change without writing anything.

Prefer a persistent install? npm install -g @stroq/cli installs the stroq command globally — then run stroq init and stroq doctor directly.

Per-agent notes

One install command per agent, and the one limit worth knowing before you rely on it. Full event tables, wire formats and every documented limit are in docs/AGENTS.md on GitHub — that file runs to 280 lines for a reason, and belongs there, not compressed onto this page.

Cursor

npx @stroq/cli init --agent cursor

Six of Cursor's hook events, failClosed on the two that block.

Limit: no Cursor event can block an editor-made file edit — it's audited, not stopped.

Codex

npx @stroq/cli init --agent codex

PreToolUse/PostToolUse on shell, apply_patch and MCP calls.

Limit: no ask in Codex's hook contract — every policy ask is enforced as a deny.

Copilot CLI

npx @stroq/cli init --agent copilot

Two events, no matcher — every tool goes through Stroq.

Limit: a hook slower than the timeout is treated as an allow, and the late deny is discarded.

OpenClaw

npx @stroq/cli init --agent openclaw

In-process plugin; before_tool_call can raise a real /approve prompt.

Limit: after_tool_call is observe-only — a poisoned result taints silently, enforced on the next call.

Windsurf

npx @stroq/cli init --agent windsurf

Six of Cascade's twelve events; every answer is an exit code.

Limit: command output is invisible to hooks, so it can't taint a session the way it does elsewhere.

Any MCP client

npx @stroq/cli init --agent mcp --client claude-desktop

A stdio proxy in front of the server — for clients with no hook API at all.

Limit: stdio only; entries with url/serverUrl (HTTP servers) are skipped, unprotected.

Also available: as a Claude Code plugin (/plugin marketplace add AGGIB/Stroq), or from source.

How it works

  1. PostToolUse — scan and taint. The output of Read, WebFetch, WebSearch, Bash, Grep, and every mcp__* tool is normalized (zero-width characters and variation-selector code points stripped, homoglyphs folded, base64/hex/URL-encoded content decoded up to two levels) and matched against the rule set. If the highest-severity match scores at or above threshold (0.6 by default), the session is marked suspect and the agent gets an inline warning to treat the content as untrusted.
  2. PreToolUse — classify and decide. Bash, file writes, Read, WebFetch, and mcp__* calls are classified into action classes (shell.network, shell.destructive, shell.exec_encoded, fs.secrets, git.push_external, config.self, mcp.side_effect, and more) and evaluated against an ordered policy — first matching rule wins, otherwise the configured default (allow).
  3. Audit. Every decision, on both hooks, is appended to a hash-chained JSONL log (~/.stroq/audit.jsonl), sensitive values redacted before they're written. stroq verify checks the chain hasn't been tampered with.

The phase names are Claude Code's; every other adapter maps its host's events onto the same pair — Cursor's beforeShellExecution/afterMCPExecution, Codex's and Copilot's PreToolUse/PostToolUse, OpenClaw's before_tool_call/after_tool_call, Windsurf's pre_*/post_* events, the MCP proxy's request and its response — so one policy file, one taint store and one audit log govern all of them.

If Stroq itself crashes while handling a high-impact tool call, it fails closed — deny — rather than silently letting the action through.

Policy

Copy policies/default.yaml to ~/.stroq/policy.yaml and edit it — rules are evaluated in order, the first match wins, and anything unmatched falls through to default. A custom policy replaces the default wholesale, so provenance and the secret egress guard are enforced only if you keep their rules (deny-origin-suspect, ask-origin-untrusted, deny-secret-egress, deny-secret-unscannable) — ahead of the ask-* rules. threshold (0–1) is the minimum scan score before a result taints a session as suspect. Set STROQ_HOME to relocate all state to a different directory.

Commands that only read the security config — cat, grep, git status/diff/add, and the like — are classified as ordinary reads, not config.self, so they stay allowed; opening it in an editor or otherwise writing to it is what triggers config.self (deny) or config.self_touch (ask).

Provenance

origin.untrusted fires when a proposed action contains an atom that appeared in an earlier tool output of the same session; origin.suspect additionally requires that output to have scanned as suspect. Only some atoms count: package specs (npx, pnpm dlx, uvx, npm install, pip install, cargo install, …), curl/wget piped into a shell, and base64 blobs always do; URLs and hosts count only when the action is already network-shaped, so following a documentation link with WebFetch never asks.

Package atoms already in the project's package.json, node_modules/.bin, requirements.txt or pyproject.toml are not counted for shell commands. Traces live in ~/.stroq/sessions/<hash>.prov.json (redacted excerpt ≤ 120 chars, at most 2,000 per session, mode 0600). The recovery for a false positive is stroq untaint --session <id>, which clears both the taint and the provenance trace.

Provenance is text-level: an agent that reads a poisoned page and then writes its own command is not attributed this way — that is what taint and the policy rules above are for.

Secret egress guard

secret.egress fires when an egress-shaped action (shell.network, network.fetch, mcp.call, mcp.side_effect, git.push_external, shell.exec_encoded) carries the exact value of a known secret. Known secrets are the credential-named or vendor-shaped values found in the working directory's .env* files, ~/.aws/credentials, ~/.npmrc, ~/.netrc, ~/.docker/config.json, and credential-named environment variables.

The index at ~/.stroq/secrets.json holds only sha256(salt + value), the key name and the file path — never the value itself. The whole argument is scanned in overlapping 256 KiB windows, up to 2 MiB total, so padding buys an attacker nothing up to that size; past it, the action is denied as unscannable rather than let through half-checked. The matched value is redacted from the audit summary as [REDACTED:<name>].

What it doesn't catch: the guard matches secret values in the arguments of an outbound call, so it doesn't know what a command will go on to read — curl -d @~/.aws/credentials … is covered by fs.secrets, not this. Matching is exact: a value split across arguments, base64-encoded, or DNS-encoded is not matched. $VAR shell expansion happens after Stroq sees the command, so curl -H "Authorization: Bearer $TOKEN" is never flagged — the recommended way to pass a credential. Replay

Every guard, ours included, answers one question in the moment: should this call be allowed. After the session is over a different question is the one that matters, and nothing answers it — the agent worked for hours, something went wrong at the end, and the transcript doesn't say which piece of text it read turned into which action.

stroq replay reconstructs that. It groups the session into the content the agent read and, under each, the actions that traced back to it: the exact fragment carried over, how long afterwards, and the rule that stopped it. It adds no telemetry — both halves of the link were already on disk.

npx @stroq/cli replay --last

It reads the transcripts your agent already keeps, so it answers for sessions that ran before Stroq was installed — no install, no config, nothing to set up first. It runs against a throwaway home and never taints a live session. --transcript <path> replays a specific file, --json emits the model, --list names the sessions in the log.

Attack corpus

stroq attack replays recorded hook events from twelve public incidents and eight synthetic matrix cells — Sentry agentjacking, s1ngularity, RoguePilot, Comment-and-Control, ToxicSkills, the rm -rf ~ horror story and more — through the engine with your policy in throwaway directories, and reports which of them would get through.

20 scenarios: 15 blocked, 5 asked, 0 passed through — every attack was stopped.

The exit code is 1 when any scenario doesn't behave as expected, so a weakened policy.yaml fails CI. stroq attack --fuzz crosses every scenario with every evasion mutation in the set (invisible characters, homoglyphs, base64, bidi overrides, padding) and reports the variants that reach allow — the escape list is the deliverable, and the exit code is 1 whenever anything escapes. Full scenario list: the guide on GitHub.

Exposure & inspect

stroq attack tells you what your policy would do. stroq exposure tells you what actually reaches you on this machine — which agents run here, which of them Stroq isn't installed for, which MCP servers bypass the proxy, what config keys widen privilege, and what the repository in front of you runs when you open it. Exit code 1 on any finding, so it works in CI or a pre-commit hook.

stroq inspect <dir> answers the same question for a repository you haven't opened yet, which matters because agents run git status at startup — before any trust prompt a hook could gate on. stroq inspect --env prints two GIT_CONFIG_* exports that neutralise a hostile .git/config before the agent ever touches it.

npx @stroq/cli inspect ./that-repo-someone-sent-me

Trust

stroq untaint clears a session and forgets — re-reading the same file re-taints it. stroq trust <file> waives a false positive permanently, pinned to the file's exact sha256, so any change to the file taints again. The list lives in ~/.stroq/trust.json, itself protected as config.self, and every waiver is written into the audit chain next to the verdict it waived — never a silent hole. Waiving a taint never waives the always-deny classes (secret.egress, config.self, shell.exec_encoded).

Guarantees & limits

Stroq is young; here's what it actually gives you today, and the honest edges.

  • Fail-closed: if Stroq errors out while handling a high-impact PreToolUse call, the action is denied, not silently allowed — including on a hook timeout, where a watchdog answers first at 60% of the agent's own timeout.
  • stroq doctor checks that the hook is still Stroq's, not just that one is there — a config rewritten to point at a different binary with the same command tail fails the check.
  • Every adapter's hook contract is narrower than Claude Code's, in its own way — see per-agent notes above and the full detail in docs/AGENTS.md.
  • Hooks are not an enforcement boundary. They can be turned off or bypassed by the agent's own settings. Stroq raises the cost of an attack and makes it auditable — it doesn't make an agent immune. Run stroq exposure to see what's actually enforced on your machine.
  • Latency: roughly 100–250 ms per hook invocation, dominated by Node process start-up rather than the scan itself.
  • Regex denial-of-service is mitigated, not eliminated: a build-time performance gate keeps known-slow patterns out of the shipped rule set; a scan that still runs past budget at runtime fails closed rather than returning clean.
  • Shell quote-splicing evasions are known (for example c"u"rl) — see SECURITY.md for the current out-of-scope list.

Full list, unabridged: the guide on GitHub.

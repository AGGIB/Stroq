Past-session check

Find known credentials in past AI coding agent sessions.

Stroq checks a saved Claude Code, Codex CLI or Cursor session for credential values known on your machine. It names the source, tool call and time without printing the value. You can inspect sessions recorded before installing Stroq hooks.

What does stroq sent check?

For one selected session, Stroq reads recorded tool calls and results and compares their text with the current values it can index from the working directory's .env* files, common credential files in your home directory and credential-named environment variables. A match is reported as a credential name and source, with the call where it appeared. It also records when a tool read or named a credential file; naming a path in a shell command is weaker evidence than a file-read result.

The report includes coverage: how many values were indexed, which files supplied them, how many calls were read and whether tool results were available. This matters when a scan returns no findings.

How to run it

Run the first command from the project directory you want to inspect. --last selects its newest available session across the three supported readers. A transcript path lets you choose a Claude Code or Codex CLI session explicitly.

npx @stroq/cli sent --last
npx @stroq/cli sent --transcript /path/to/session.jsonl
npx @stroq/cli sent --last --json

No prior Stroq hook installation is needed for the transcript scan. For repeat use, npm install -g @stroq/cli avoids an npx package fetch at invocation time. See the full guide for the audit-log form, Cursor session addressing and --fail-on-finding.

What a finding means

A value found in a saved tool result or tool argument is evidence that the recorded session contained that known credential. The output distinguishes these two locations and identifies the relevant call. A credential-file row distinguishes a file read from a path merely named in a shell command.

Provider delivery is not verified. A local transcript cannot prove which bytes a model provider received, whether a result was truncated before transmission, what the provider retained or whether anyone used the credential. Treat a finding as a reason to investigate and rotate a sensitive credential, not as proof of an external breach.

A finding does not change the command's default exit status: a produced report exits 0 even with findings. Use --fail-on-finding when a scheduled check should return 1 on a finding. A missing session or one with no recorded tool calls also returns 1.

What stays on your machine?

The scan runs locally. It reads the chosen local session and credential sources to perform exact-value matching; it does not upload their contents for analysis. Stroq refreshes a local index of salted hashes and writes names and source paths, never matched values, to the human-readable or JSON report. Review that report before sharing it, because names, paths and command summaries can still be sensitive.

On a first npx invocation, npm may download the CLI package. Install the package ahead of time if you need the check to run without a package download.

Coverage and limits

  • Known values only. A credential rotated or deleted since the session is absent from the current index and cannot match. Split, encoded or otherwise transformed values may also be missed.
  • One saved session at a time. --last chooses the newest session associated with the current directory; it does not certify every prior session or every agent on the machine.
  • Three transcript readers. Claude Code, Codex CLI and Cursor are supported. Cursor uses a SQLite store and needs a Node version with node:sqlite; Stroq reports when that reader is unavailable. Windsurf, Copilot CLI and Antigravity histories are not claimed here.
  • Audit logs are narrower. When scanning Stroq's own audit log instead of an agent transcript, tool-result text is unavailable; only call arguments and credential-file evidence can be checked.

No findings means no indexed value was found in the material this run could read. Check the report's coverage section before drawing a conclusion about the session.

What to do next

  1. Review the named call and source in the local transcript. Confirm whether the credential is still active and rotate it if exposure matters.
  2. Run stroq exposure to inspect which agent channels and MCP servers are actually guarded on this machine.
  3. Use stroq init and stroq doctor to add and check forward-looking hooks. The security limits explain where hooks cannot enforce a boundary.

For transcript formats, exact commands and report fields, see the full guide and source code on GitHub.
